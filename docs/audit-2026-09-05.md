# Code audit: 2026-09-05

This is a focused source audit and repair pass, not a production certification.
The starting revision was `898b461`. The review covered request parsing, response
framing, static serving, buffered caching, HTTP/2 and HTTP/3 protocol boundaries,
and the admin/config lifetime paths. Git hooks, build configuration, and the
verification scripts were inspected before running them.

No production host was changed or verified during this pass. Existing deployment
notes describe historical deployments, not evidence that these fixes are live.

## Still open, in build order

1. **P1: HTTP/2 outbound flow control is missing.**
   `src/http2_server.zig:215` acknowledges SETTINGS without applying the peer's
   initial window; `:238` ignores WINDOW_UPDATE. `src/http2_runtime.zig:121`
   sends all DATA in fixed chunks without connection or stream send windows.
   Small successful requests do not establish correct large-response behavior.
   Add connection-owned send state, bounded pending responses, independent
   stream progress, SETTINGS validation, and window-aware flushing. Acceptance:
   zero/small windows stop DATA, updates resume only eligible streams, and reset
   or stalled streams cannot block unrelated traffic.

2. **P1: Protocol state validation and client conformance remain incomplete.**
   `src/http2_server.zig:41` requires END_HEADERS on the initial HEADERS frame;
   CONTINUATION and stricter frame/stream lifecycle handling remain. HTTP/3's
   `src/h3_native.zig:161` rejects Huffman strings, and
   `src/http3_server.zig:1525` constructs a localhost self-signed certificate
   instead of using configured domain certificates on that path. The QPACK
   encoding repair is not a full QUIC/TLS interoperability result. Require
   independent h2/h3 clients, configured certificates, loss/reordering tests,
   bounded flow control, and stream-lifecycle coverage before advertising broad
   compatibility. The shared H3 field validator is not yet full pseudo-header
   semantic validation.

3. **P1: Admin bootstrap and session lifecycle need hardening.**
   `src/admin_runtime.zig:490` allows first-account setup when credentials are
   absent. Do not expose that listener before local setup: there is no separate
   bootstrap proof. `src/admin_support.zig:734` accepts a persistent shared
   session value; logout only clears the browser cookie (`admin_runtime.zig:509`).
   Cookies lack Secure (`admin_support.zig:743`). Add one-time bootstrap proof,
   expiring/revocable sessions, TLS-aware cookies, and explicit mutation-origin
   checks. SameSite is helpful but not a complete sibling-subdomain boundary.

4. **P1: Static roots are not a filesystem sandbox.**
   The new lexical check does not prevent a permitted filename from being a
   symlink to a private file. `src/static_files.zig:380` stats paths and the
   readers later reopen them; symlink containment and replacement races remain.
   Implement a documented root-relative file-opening policy and serve from the
   validated handle. Keep private files outside published roots. Also audit
   PHP execution aliases separately: their phpinfo guard currently matches the
   request spelling `/test.php`, not the final resolved script identity.

5. **P2: Cache accounting and reload retention are not fully bounded.**
   `src/buffered_cache.zig:70` and `src/static_cache.zig:81` limit body bytes,
   excluding keys, headers, and entry metadata. Zero-byte entries can grow the
   cache without consuming that budget. Both stores use linear scans under a
   mutex. `src/config_store.zig:41` retains snapshots until store shutdown.
   Add total allocation/entry budgets and tests for empty responses, then
   reclaim snapshots only after readers release them. The new pointer-based
   cache namespace relies on snapshots not being recycled; switch to monotonic
   generation identifiers before changing that lifetime.

6. **P2: Release acceptance is still narrower than deployment readiness.**
   Add Linux execution, large-file/multiplex/slow-client soak, real php-fpm,
   upstream failure tests, TLS renewal/rollback drills, and protocol conformance
   gates. Do not expand disk caching or make performance claims ahead of the
   correctness and memory bounds above.

## Compatibility changes

Static handlers now return 404 for hidden files and PHP-family source names.
Configure an executable PHP handler for scripts; publish assets in a separate
public root. `.well-known` remains available, but hidden children inside it do
not. Request framing that was previously accepted permissively can now return
400. Conservative cache bypasses can reduce hit rate until freshness metadata
and bounded storage are implemented.
